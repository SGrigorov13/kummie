# G1 — KUMMIE Pixel Run (mini-game in the mobile app)

Status: **spec, waiting for owner confirmation of the original-IP direction (D-013).**
Depends on: M0 (mobile shell), M1 (accounts + API) for server sync. The re-skin and IP rework
(parts A–B) can start right after M0.

## Source

`KUMMIE-Pixel-Run-Package.zip` (received 2026-11-16): `kummie-pixel-run.html` (single-file
HTML5 Canvas + Web Audio game), `kummie-bridge.d.ts`, `CLAUDE_INTEGRATION_GUIDE.md`.

**The original package must not be committed.** Keep it outside the repo or in the git-ignored
`incoming/` folder and use it only as a reference for the engine code. Reasons:

1. **Third-party IP.** It contains BLACKPINK and BTS song titles and structures, romanised song
   lyrics synced to the timeline, real members as playable pixel characters (hair/colour
   likenesses), invented quotes and "autographs" attributed to real members on the cards, MV-based
   stage themes and fandom slogans. In a commercial app for teens this infringes copyright
   (lyrics, songs), personality/likeness rights and trademarks, implies endorsement by the artists,
   and would be rejected under Google Play's IP policy. It also breaks this repo's non-negotiable
   rule: no third-party IP in our own assets.
2. **Leftover sandbox code.** The file was exported from Gemini Canvas and still contains injected
   `data-bard-client-injected` scripts with a Firebase config and a short-lived auth token from that
   sandbox, a `postMessage(..., '*')` editor hook and a WebSocket interception config. None of this
   may ship.
3. **Runtime CDN dependencies.** Tailwind CDN, Google Fonts and JSZip load from the internet;
   the in-app game must work offline and use the self-hosted brand fonts.

## A. Keep (engine)

- Canvas renderer, physics, the 10 platform algorithms, section-based stage timeline, Web Audio
  synth (oscillator beats), optional beat analyzer, difficulty levels (EASY / HARD / MASTER),
  ranks (S / A / B / C), card counts and tier rule (Normal → Silver at 5 → Gold at 10 → Diamond
  at 20), `KummieBridge` event model (`KUMMIE_GAME_READY`, `KUMMIE_STAGE_COMPLETE`,
  `KUMMIE_ALBUM_SYNC`, `hydrateAlbum`).

## C. Brand re-skin (from `docs/brand/README.md`)

- Colours only from `@kummie/brand` tokens. UI ground Violet, text Ink, actions Glow with Ink text,
  long-form panels Paper. **Hot Pink only for the star**, never for tiers or decoration (pink means
  LIMITED in the shop). Spotlight is not used for tiers either (it means OFFICIAL). Tier visuals use
  Paper / White-with-Ink-outline / Glow / Violet-with-Glow-edge plus a text label — never colour
  alone.
- Fonts: Archivo Black for titles (≥ 20px), Space Grotesk for UI text, Space Mono uppercase for HUD,
  timers, ranks and card serials. Pixel style lives in the sprites only (drop Press Start 2P,
  Rubik and Caveat). Same Cyrillic caveat as D-003.
- Icons: brand icon language (24px grid, 2px stroke, rounded); the star and equaliser are the
  game's signature shapes. The equaliser is the loading animation.
- Motion: 180–240ms ease-out for UI; honour reduced motion (no screen shake, reduced particles).
  No sound until the player starts a stage.
- Teen-safe: no shop links or prices inside the game, no countdowns outside gameplay itself, no
  pressure copy, no purchasable randomness. Cards are earned only by playing.
- Bulgarian and English copy through `packages/i18n` (pass the locale in `hydrate`).
- No external requests: all CSS/JS/fonts inlined or bundled. Replace Tailwind CDN with plain CSS
  using the tokens.

## D. Mobile integration (`apps/mobile`)

- Add `react-native-webview` with `npx expo install react-native-webview`.
- Bundle the built game as `apps/mobile/assets/games/pixel-run/index.html` (built from
  `games/pixel-run/` source in the monorepo, so it can be linted and tested). Load it via
  `expo-asset` as a local file.
- Screen `app/games/pixel-run.tsx`, opened from Home and from the Collection tab (not a sixth tab).
- WebView settings: `javaScriptEnabled`, `domStorageEnabled`, `originWhitelist` limited to the
  local file, `onShouldStartLoadWithRequest` blocks every external navigation, no file access
  beyond the asset, `mediaPlaybackRequiresUserAction` respected.
- Bridge, game → app: messages arrive through `window.ReactNativeWebView.postMessage`. Parse with a
  Zod schema in `packages/contracts` (`source` must be `KUMMIE_PIXEL_RUN`); ignore anything else.
  Remove the `window.parent.postMessage` branch.
- Bridge, app → game: after `KUMMIE_GAME_READY`, call
  `window.KummieBridge.hydrate({ locale, album })` via `injectJavaScript`.
- Offline: queue stage results in AsyncStorage and send them when online. Guests can play; their
  local album merges into the account on sign-in.

## E. Backend (`apps/api`)

Tables (Drizzle migrations):
- `game_stage_result` — id, customer_id, game_id (`pixel-run`), stage_id, difficulty,
  total_time_ms, penalty_ms, rank, client_event_id (unique, for idempotency), created_at.
- `game_card` — customer_id, game_id, stage_id, character_id, rank, count, tier, first_unlocked_at,
  updated_at; unique (customer_id, game_id, stage_id, character_id, rank).

Endpoints (authenticated customer):
- `GET /me/games/pixel-run/album` → album in the shape `hydrate` expects.
- `POST /me/games/pixel-run/results` (`KUMMIE_STAGE_COMPLETE`) → stores the result, increments the
  card, **server computes tier** from count; idempotent by `client_event_id`; plausibility checks
  (time not below the stage's minimum, known stage/character/difficulty) and rate limiting.
- `POST /me/games/pixel-run/album/sync` (`KUMMIE_ALBUM_SYNC`) → used only to merge an offline or
  guest album: per key take the maximum count, never decrease; server stays the source of truth.

Rules:
- Game cards are separate from the shop collection (`OwnedItem` for real products). The Collection
  tab shows both, clearly labelled.
- No public leaderboards or profiles (minors). No Kummies or discounts for playing in this
  milestone — any reward link to commerce is a separate owner decision.
- Account deletion removes game data.

## Definition of done

- Game runs offline inside the app on Android, in BG and EN, fully on-brand, with original content
  only; a repo-wide check finds none of the original group, member or song names in `games/` or
  `apps/mobile/assets/`.
- Completing a stage while signed in creates the card on the server; reinstalling the app and
  signing in restores the album.
- Unit tests for tier computation, merge logic and message validation.
